## Decisão de produto

Uma única ficha **DeepSeek Harness** em Inteligência artificial → Agentes de desenvolvimento, com atalho contextual em Desenvolvimento. `app.deepseek-harness` tem instalador e estado próprios. **DeepSeek Proxy** permanece ficha de conexão/modelo, com texto explícito de que não instala nem inicia Harness. Contas e conexões mostram canais distintos: **Conta DeepSeek para Harness** (login no navegador, perfil/saldo quando consulta funcionar), **Chave API DeepSeek** (custo e validação independentes) e **DeepSeek Proxy** (sessão terceirizada). Nunca inferir elegibilidade de um canal a partir de outro; nenhum fallback silencioso entre conta, API paga, proxy ou outro provedor.

Jornada simples: **Instalar → Conectar conta ou API → Escolher pasta → Verificar → Abrir → Parar**. Estado por etapa, motivo acionável e progresso; `instalado` não é `pronto`, `login` não é `cota`, porta aberta não é modelo operacional. Modo avançado expõe perfil `web`/`headless`/`acp`/`sdk`, plugins, modelo/endpoint, política de ferramentas, autostart e atualização. `acp` pode servir agentes/IDEs compatíveis mediante configuração explícita; aplicativo Desktop upstream exige avaliação de distribuição à parte. Operação local sob demanda; autostart fica opt-in após gate de reabertura autenticada. Superfície fica marcada **Experimental** até gates reais. Nenhum workload inicia no boot por instalar o pacote.

## Contratos antes do código

- Backend CLI: `pz ai deepseek-harness plan|status|install|update|start|open|stop|doctor|uninstall --json`; `config` e `auth` como comandos separados. `plan/status/doctor` read-only, sem invocar comandos upstream que inicializem `DSH_HOME`; operações mutáveis têm preview, lock e JSON estável (`state`, `reason`, `nextAction`, `version`, `profile`, `port`, `authRoute`, `sandboxEnforcement`). Erro essencial retorna código não zero; saída stdout não contém segredo.
- Fonte canônica: manifesto próprio de aplicativos/agentes para `dsh`; **não** acrescentar Harness como `proxy` em `assets/ai/proxy-manifest.json`. Registrar ações no `linux/ui_native/catalog.py`, inventário `linux/ui_native/product_inventory.py`/JSON e equivalente Windows. Manter um instalador por plataforma e atalhos para o mesmo `appId`.
- Estado persistido separado do binário: `DSH_HOME` explícito, diretórios de config/dados e permissões restritas; migração de schema com backup verificável. Upstream grava chave em `$DSH_HOME/.credentials.yaml` e perfil em `$DSH_HOME/profiles/web/cordis.patch.yml`; PhaseZero só injeta referência/descritor, nunca replica segredo em JSON de status, argv, journal ou log. [Configuração oficial](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.1-rc.2/docs/user/guide/providers.md).
- API e conta: upstream oferece chave API oficial e login de conta via navegador, com perfil/saldo consultáveis. Conta usa callback local; uma falha de login/balanço não apaga chave API nem bloqueia rota API. 401, 402/cota, timeout, offline, conta trocada e versão incompatível têm estados diferentes. Gravação e revogação da credencial ficam com o upstream; PhaseZero só mostra projeção redigida e dispara ações explícitas. [Conta](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.1-rc.2/packages/credentials/deepseek-account-platform/README.md), [rota de inferência da conta](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.1-rc.2/packages/llm/llm-deepseek-account/README.md).

## Sequência e gates

1. **R0 — decisão e baseline**: revalidar `main`, roadmap de Homelab, CI, estado do host, upstream e recursos. ADR escolhe formato de instalação e isolamento. Falha de integridade, arquitetura não suportada ou licença bloqueia R1.
2. **R1 — gerenciador Linux**: DSH-001/002/003/008, em worktree dedicado. Testes de host limpo em container/VM descartável; stubs de registry, download quebrado, disco cheio, dois processos e rollback. Não instalar no host de desenvolvimento nessa fase.
3. **R2 — conta, API e isolamento**: DSH-004/005/007/009. Teste local sem gasto com provedor falso; validar sandbox funcional com operações negadas, sem assumir que `workspace-write` impede leitura/rede. `deepsproxy` e 9Router permanecem opções separadas; integração neles depende do gate de grants por requisição já aberto no PhaseZero.
4. **R3 — UI**: DSH-006, ações e inventário únicos. Testes de hit-test, foco, escala, acessibilidade e cancelamento; não declarar “pronto” com base em presença de binário ou TCP.
5. **R4 — Windows e runtime real descartável**: provisionar Windows sem alterar Windows VM ocupado no host atual. Verificar ACL/sandbox `partial` com aviso e limites, bootstrap Node per-user, navegador, porta, serviço e uninstall. Exercitar Arch limpo e Windows sem dependências prévias.
6. **R5 — piloto opt-in e release**: sob orçamento de host e operador, instalar pacote PhaseZero, iniciar `dsh` em workspace descartável, validar Web UI e uma ação reversível. Testar conta real e/ou API com limite de custo consentido; registrar login, lista de modelos, cota/probe e saída. Credencial ou Windows indisponível bloqueia apenas seu gate; restante pode avançar em preview com indicação honesta, sem chamar integração de completa.

Gates mínimos: shell/Python/unit por subsistema; `git diff --check`, scanner de segredos, provenance/SBOM; CI Linux/Windows; boot em host limpo; testes de cancelamento/rollback; UI real temática; nenhuma alteração silenciosa de serviços/contas existentes. Para dizer **funcional no host**, registrar SHA do pacote, versão `dsh`, URL de origem sem token, estado do processo, sandbox enforcement, perfil, rota escolhida e resultado de tarefa real. Não registrar chaves, cookies, URL tokenizada, prompt privado ou conteúdo de arquivo.

## Limites e perguntas já resolvidas

- `dsh` oficial não depende do `deepsproxy` para existir; escolha padrão é rota oficial, com conta ou chave API selecionada pelo usuário. Proxy segue alternativo avançado e sujeito aos grants do PhaseZero.
- `dsh web` aceita `--no-open`; login da conta exige Web/callback em loopback. Publicação LAN/túnel é projeto separado com TLS, autoridade confiável e autenticação, nunca consequência de instalar. [Publicação upstream](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.1-rc.2/docs/user/guide/public-deployments.md).
- Upstream está em prévia sem auditoria; integração PhaseZero não deve afirmar segurança absoluta. Controles reduzem risco; escopo de arquivos autorizado, rede e processos ainda precisam de análise operacional.
- O trabalho de implementação usa fixtures e ambientes CI descartáveis. Não executou Harness, login, teste de modelo, instalação ou serviço no host; não alterou sessão KDE nem usou Windows VM ocupada.
