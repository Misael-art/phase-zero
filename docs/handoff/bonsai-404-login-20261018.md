# Handoff — Bonsai npm 404 e login privado

Objetivo da sessão: corrigir bloqueio local do login Bonsai causado por
`@bonsai-ai/cli/latest` HTTP 404; oferecer autodiagnóstico honesto e validar
no host antes de nova release.

Branch e worktree: `codex/bonsai-diagnose-404`,
`/mnt/sdcard/Projects/pz-bonsai-diagnose-404`, base `origin/main` em
`78604fb` (`v1.22.8`). Checkout do operador em
`/mnt/sdcard/Projects/PhaseZero` estava sujo e não foi alterado.

Alterações: `linux/ai/claude_code_manager.py` classifica `/-/ping`, metadados
do pacote e `/latest`; distingue `package-unavailable` de falha geral de rede.
`linux/ai/bonsai_login_compat.cjs` só atua no `login` explícito do pacote
0.4.19 com hash local conhecido e apenas sobre a resposta 404 de `/latest`.
O diagnóstico continua a mostrar atualização indisponível e autenticação
desconhecida. CLI diferente recusa o contorno. `/dev/tty` usa `r+b` sem buffer;
`linux/ui_native/pages/ai_dev.py` informa tentativa e limite do contorno.
O hash fixa somente os bytes observados neste host; não substitui assinatura
ou atestado de publicação do fornecedor.

Provas: no host BigLinux/Manjaro KDE, pacote `phasezero-control-center
1.22.8-1` antes da mudança; CLI local 0.4.19; npm `/-/ping` 200, pacote 404,
`/latest` 404. `bonsai-probe` do worktree retornou `package-unavailable`,
`loginAttemptAvailable:true`, `loginCompatibility:registry-404-pinned-cli`,
`authenticated:false`, `sessionUsable:false`, `proxyAvailable:false`.
Teste real de login sob PTY chegou ao fluxo de dispositivo e aguardou
interação; supervisor interrompeu a tentativa; hash da credencial permaneceu
igual. Não houve login concluído. Testes herméticos: `tests/test_claude_code_manager.py`
41 verdes, `tests/linux-ai-claude.sh` 51 verdes, três sondas de UI Bonsai com
temas reais verdes; `py_compile`, `node --check`, `git diff --check` verdes.

Estado do host: nenhuma instalação de pacote, alteração do CLI npm,
serviço, VM, boot ou sessão KDE durante implementação. `bonsai-probe` escreveu
somente cache de observação sem segredo; credencial preservada. Nenhum código
de dispositivo, URL privada, token ou valor de credencial foi persistido.

Limites: o CLI ainda depende do provedor de autenticação Bonsai. A observação
antiga `upstream-auth-disabled` não é atual; o estado atual só ficará conhecido
quando a pessoa concluir a autenticação no terminal/browser. O pacote 0.4.19
com hash diferente e instalações novas seguem bloqueados enquanto o npm 404
persistir. Proxy para outros CLI exige contrato oficial e autorização por
consumidor; presença de chave local não basta. Não marcar `ready` sem teste
autenticado real. O contorno é temporário e deve ser removido quando a
distribuição oficial voltar a funcionar.

Próximos passos: revisar diff por segredos; enviar PR; exigir CI, incluindo
gitleaks; fazer merge em `main`; publicar beta `v1.22.9` pelo fluxo canônico;
baixar pacote Arch e verificar SHA256; instalar com `phasezero-admin pacman -U`
sem reiniciar host/KDE; repetir `bonsai-probe` no pacote instalado; pedir à
pessoa que conclua o login se surgir código de dispositivo. Testar status
`authenticated` e serviço somente após login bem-sucedido.

apagar `~/.config/bonsai-cli-nodejs/config.json`. Cache não secreto de
